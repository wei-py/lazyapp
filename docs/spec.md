# lazyapp 技术栈与开发规范

> 状态：第一阶段已实现；本文仍是开发约定，具体落地契约与验证范围见第 12 节。
> 面向个人使用的本地 App 配置管理 TUI。

## 1. 定位与边界

- 管理 App 基础信息、资源、平台配置、证书、第三方服务、环境和商店资料。
- 第一阶段入口为 `lazyapp`，围绕启动初始化询问、配置编辑、文件管理和 Doctor 完整性检查展开。
- 本地文件是唯一持久化来源，默认离线运行；不引入账号、服务端、数据库、云同步或遥测。
- 不负责构建、签名执行、发布、自动申请证书或调用第三方服务变更远端状态。
- 环境按需创建，支持自定义名称；不强制每个平台都有 development / production。
- `lazyapp.md` 保留产品构想；本文约束技术实现与交互。涉及明文风险、路径和 Git 忽略方式时，以本文的安全约束为准。
- 「必须／禁止」为实现底线；「优先／建议」允许在明确原因后调整。未涉及的功能不因本文提前实现。

## 2. 技术栈

| 类别 | 选型 | 约束 |
| --- | --- | --- |
| 运行时、包管理 | Bun | 统一使用 Bun 安装、运行与测试，提交 `bun.lock`，不混用 pnpm / npm 锁文件 |
| 开发语言 | JavaScript，ES Modules | 不使用 TypeScript；通过 JSDoc 描述跨模块契约 |
| TUI | `@opentui/core` | 直接使用 OpenTUI Core，不引入 React / Vue 渲染层；Ratatui 仅可作为交互参考，不作为依赖 |
| 代码风格 | ESLint + `@antfu/eslint-config` | 使用同一配置检查和修复风格，不并行维护第二套格式规则 |
| 测试 | `bun:test` | 覆盖配置、存储和关键交互状态，不引入 Vitest、浏览器组件测试或 Playwright |
| 持久化 | JSON + 原始资源文件 | 配置可人工阅读和编辑；证书、图片保持原始格式，不内嵌为 Base64 |
| 文件与进程 | Bun / `node:` 内置 API | 优先内置能力；外部程序仅在具体功能需要时引入 |
| 工具与日期 | 原生 JavaScript 优先 | 不因旧规范预装 xe-utils、dayjs；复杂需求出现后再统一选型 |

- 初始化工程时记录实际验证的 Bun 版本与 OpenTUI 版本；升级后验证启动、输入、布局和终端恢复。
- 首要支持 macOS 交互终端。App 可管理的平台不等于工具已支持的运行系统；Linux / Windows 支持必须实测后声明。
- 已配置 `bun run dev`、`bun run lint`、`bun run lint:fix`、`bun test`；启动参数与实际验证范围见第 12 节。
- 分发与打包方式单独按实际验证结果确定，不预设单文件可执行文件包含全部原生依赖。

## 3. 代码组织与依赖方向

按业务模块组织，目录按需创建，不先堆空壳。

```text
src/
├── main.js             # 入口、参数、启动与退出
├── app/                # 应用壳、导航、焦点与生命周期
├── features/           # 按需添加 app、assets、platforms、services 等模块
├── shared/             # 已有复用需求的控件与纯函数
├── storage/            # 配置读写、文件导入、路径与写入保护
└── config/             # 工具自身配置与默认值
```

- 依赖方向：`main → app → features → storage / shared / config`；底层不得反向依赖应用或业务模块。
- feature 之间不直接读取内部状态，通过应用层协调；真正共享的模型或逻辑提取到已有公共层。
- 不再同时创建 pages、components、layouts、stores 等功能重叠的目录。
- UI 负责展示与输入；业务逻辑负责校验与操作；storage 负责磁盘副作用。控件禁止直接写文件或启动进程。
- 简单逻辑就地实现；出现真实复用再抽取，不为单个调用创建通用框架、插件系统或依赖注入容器。
- 模块文件使用 kebab-case，变量和函数使用 camelCase，类使用 PascalCase，模块级固定常量使用 UPPER_SNAKE_CASE。
- JSDoc 用于导出函数、共享数据结构及不明显的约束，说明参数、结果和必要的异常语义。禁止给每个局部变量、回调重复写无信息量注释。

## 4. 状态与操作模型

- 区分三类状态：磁盘配置快照、未保存编辑草稿、焦点／选择项／滚动等临时 UI 状态。
- 一个状态只由一个明确的所有者修改；不在多个控件中复制同一份配置或 loading 状态。
- 修改表单仅更新草稿，保存成功后才更新磁盘快照并清除 dirty 标记。保存失败保留草稿。
- 离开未保存页面、切换工作区或正常退出时，提供「保存／放弃／取消」；默认不丢弃修改。
- 取消编辑不得写盘；启动询问明确回答 `y` / `yes` 前不创建工作区文件。
- 加载、成功、空、错误、取消分别建模。过期异步结果不得覆盖当前页面或新操作的状态。

## 5. 键盘、焦点与交互

键盘可完成全部核心操作，采用 Vim 风格导航，但不实现完整 Vim 模式系统。鼠标仅作增强。

| 按键 | 非文本编辑上下文中的含义 |
| --- | --- |
| `j / k`、`↓ / ↑` | 焦点面板内下移／上移；移动即刷新详情预览 |
| `h / l`、`← / →` | 焦点在面板之间前移／后移（分类 → 列表 → 详情） |
| `1 / 2 / 3` | 直接聚焦分类／列表／详情面板 |
| `Tab / Shift+Tab` | 在面板之间循环切换；字段编辑中改为切换字段 |
| `Enter` | 分类面板进入列表、列表面板进入详情、详情面板编辑当前字段；详情末行执行保存 |
| `Esc` | 关闭最上层浮层或取消当前编辑；焦点按 详情 → 列表 → 分类 回退，分类面板上请求退出 |
| `/` | 进入路径搜索输入（分类面板上使用时会先聚焦列表） |
| `g g / G` | 焦点面板首项／末项；`g g` 序列超时为 500 ms，焦点变化时清除 |
| `Ctrl+s` | 保存当前草稿；详情面板末行同时提供可聚焦的保存行 |
| `?` | 打开当前上下文的快捷键帮助 |
| `q` | 请求退出，执行未保存检查 |
| `Ctrl+c` | 有顶层弹窗时关闭该弹窗；否则请求退出 |

- 焦点面板使用绿色边框，当前选中行使用浅蓝底。文件／配置行缺失为红字、存在为绿字，选中后仍保留状态颜色；其他选中项使用深色字。编号标题嵌入边框，列表右下角显示当前位置／总数。
- 浏览分类、列表和详情本身不触发确认；只有改变分类、改变条目、改变搜索结果或新建目标会进入未保存确认。

- 文本输入获得焦点后，`j/k/h/l/q/?/g/G` 和 `/` 都按普通字符输入；方向键按文本编辑语义处理，不触发列表导航。
- 快捷键由统一分发层按「顶层弹窗 → 当前控件 → 当前页面 → 全局」处理，消费后停止传播。
- 任意时刻只有一个键盘焦点目标；选中态与焦点态必须能区分。
- 弹窗捕获焦点和输入，背景不可操作；关闭后恢复原焦点，原控件已删除时回退到最近可用控件。
- 删除、覆盖文件和放弃修改必须明确确认，默认焦点放在取消项；生产环境操作清晰标识目标。
- 底部展示当前可用快捷键，不宣传不可用操作。输入模式和任务状态有明确文字提示。

## 6. 布局、层级与滚动

- 固定终端视口应用壳：左列顶部为紧凑工作区信息，右列底部为状态面板，最底行展示当前快捷键。
- 双栏左侧占约 32%：工作区、`[1]` 分类、`[2]` 列表纵向堆叠；右侧为从顶部开始的 `[3]` 详情与下方状态。移动分类或列表选中项立即刷新详情。默认使用细圆角边框、绿色焦点框与整行蓝色选中背景；`TERM=dumb` 时使用 ASCII 边框。
- `layoutMode` 阈值不变：宽度 ≥ 100 列且高度 ≥ 24 行使用双栏；宽度 60–99 列且高度 ≥ 16 行使用单栏，工作区下方纵向显示焦点面板与关联预览，编号在边框标题中，不另设页签行；其他尺寸显示空间不足提示，仍允许退出。
- 不沿用 CSS z-index。只保留「基础内容 → 弹窗 → 弹窗内选项」的覆盖顺序；普通通知放在状态栏，禁止夺取焦点或盖住确认操作。OpenTUI 中该顺序由渲染节点创建顺序决定，弹窗节点必须在所有面板节点之后创建，否则面板会覆盖对话框。
- 每个面板明确滚动边界，只有焦点所在区域处理滚动；列表与详情可各自滚动，但同一输入不能同时滚动两处。
- resize 后重新计算可用空间，保留草稿、当前项与可恢复的滚动上下文，禁止越界绘制。
- 导航时选中项始终可见；返回列表、刷新数据或请求失败时，优先按稳定 ID 恢复当前项与滚动位置，目标消失时选择最近有效项。
- 大列表仅构建可视范围附近的行；禁止每次按键重建全部数据或读取全部资源内容。
- 路径、中文、全角字符按终端显示宽度裁剪，不使用字符串长度代替列宽；长文本提供详情查看，不撑破布局。
- 不依赖 Nerd Font、Emoji 或复杂 Unicode 图标；状态使用文字，颜色仅作辅助，边框提供 ASCII 降级。
- 颜色统一使用语义 token：text、muted、accent、success、warning、error、border、focus；不得在业务模块散落 ANSI 转义序列。

## 7. 终端生命周期

- 启动前检查交互所需的 stdin / stdout TTY；不满足时向 stderr 输出说明并非零退出，不进入 raw mode。
- 渲染器统一持有终端；进入 TUI 后禁止 `console.log` 或子进程直接往终端写入，避免破坏画面。
- raw mode、备用屏幕、光标与事件监听由入口统一管理；正常退出、初始化失败、可捕获异常和 SIGINT / SIGTERM 均执行幂等清理。
- 正常用户退出或拒绝初始化返回 0；启动、读写或未恢复的运行错误返回非零；信号退出使用对应约定退出码。
- SIGTERM 尽力恢复终端，但不弹出等待输入的对话框，也不自动保存草稿；SIGKILL 等不可捕获终止无法保证清理或草稿保留。
- 文件操作及外部命令异步执行，不阻塞输入循环。外部命令使用程序名与参数数组，禁止将用户输入拼接进 shell 命令。
- 默认捕获子进程输出；需要交互式外部程序时先暂停 TUI、恢复终端，结束后重建画面与焦点。
- 若支持后台挂起／恢复，必须同步处理终端状态；未经验证不绑定挂起快捷键。

## 8. 数据与文件约定

### 工作区与配置

- 工具源码目录与用户项目中的 `<project>/lazyapp/` 数据目录是两种概念，不混用。
- 默认只查找 `<cwd>/lazyapp/app.json`；不自动向父目录扫描并写入其他项目。不存在时询问初始化，取消不留文件。
- 目标目录已存在但不是有效工作区时显示冲突，不静默接管或覆盖。界面持续显示实际工作区路径。
- `app.json` 保存 App 元数据及 `schemaVersion`；平台配置、服务、环境和资源按 `lazyapp.md` 的分类按需落盘。
- JSON 使用 UTF-8、2 空格缩进和末尾换行。字段默认值、必填条件和敏感属性集中定义，UI 与 Doctor 复用同一套规则。
- 环境名称必须是安全的单个目录名，不接受空值、`.`、`..`、分隔符和路径穿越；大小写冲突按目标文件系统处理。
- 工具设置与业务环境分开；工具配置集中读取，不照搬 `VITE_*` 或自动加载业务 `.env` 文件的机制。
- 界面语言是用户级偏好，保存于 `$XDG_CONFIG_HOME/lazyapp/settings.json`（XDG 路径须为绝对路径）；未配置时使用 `~/.config/lazyapp/settings.json`。格式为 `{"schemaVersion":1,"language":"en"}` 或 `"zh"`。文件不存在时默认 English 且读取不创建文件；仅明确选择语言才保存。设置不属于 App 工作区。
- 语言偏好使用私有目录／文件权限、同目录临时替换和独占写锁。损坏 JSON、不支持的版本／语言、设置路径符号链接均拒绝覆盖；保存失败保持当前语言与业务草稿。保留未知设置字段。
- 不支持的 schemaVersion 明确报错并禁止写入；迁移必须有具体版本转换、备份和确认，不静默丢字段。
- 读取失败或 JSON 损坏不得当作空配置覆盖；保存已支持版本时保留未编辑字段。

### 文件导入与路径

- 默认复制文件到工作区；用户也可明确选择引用外部文件。复制前验证源文件可读，覆盖目标前确认。
- 工作区内的引用统一相对工作区根目录保存，禁止混用相对各级 config.json 的路径。外部引用保存明确的绝对路径，并提示不可随工作区迁移。
- 例如 iOS 证书内部引用为 `platforms/ios/production/certificate.p12`，解析时以工作区根目录为基准。
- 管理目录内的写入、删除必须校验规范化路径及已有父目录的真实路径，禁止通过 `..` 或符号链接越出工作区。
- 外部引用只读：解除引用不删除源文件；复制导入同样不修改源文件。

### 写入可靠性

- 单文件保存使用同目录临时文件写入后替换，成功前不得截断原文件；失败清理临时文件并保留草稿。
- 同一工作区串行写入；最初实现采用工作区独占写锁，第二个实例拒绝进入可写状态。锁有所有者信息，异常遗留锁只在确认失效后处理。
- 写入前比较读取时的内容与当前磁盘版本；检测到外部修改时提示重新加载或显式覆盖，不静默覆盖。
- 外部编辑器不遵守锁，写前检查不保证消除并发竞态；不承诺与其他程序同时写入安全。
- 初始化等多文件操作先在暂存区准备，校验通过后提交；涉及已有文件的多文件变更必须定义恢复方案，不把多次 rename 当成整体原子事务。
- 删除采用逐项明确目标的操作，禁止根据未经校验的配置路径递归删除目录。

## 9. 敏感信息与本地安全

- 允许按个人使用方式在本地保存明文密码、Token 和私钥，但必须明确：本地目录不是加密保险箱；备份、同步软件、恶意进程和误提交仍可能泄漏数据。
- 不默认引入主密码、Keychain 或加密服务，也不把「未上传 Git」当成安全保证。
- 密码、Token 等输入默认遮蔽；已有敏感值默认隐藏，仅在明确操作后显示，离开详情即恢复隐藏。
- 日志、错误、Doctor 和普通摘要禁止输出敏感值、证书正文或完整配置；敏感字段不参与普通全文搜索。
- 复制敏感信息只能由用户显式触发，并提示剪贴板可能被历史工具记录；不自动复制或宣称已安全清除历史。
- POSIX 下新建数据目录使用 `0700`、配置／证书／临时文件使用 `0600`；现有权限过宽时提示，不修改外部引用文件权限。
- 初始化在**数据目录内部**创建 `lazyapp/.gitignore`，内容为 `*`，忽略该目录内所有未跟踪文件；不在这里写 `lazyapp/`，它匹配的是下一级同名目录。
- `.gitignore` 不会取消已有 Git 跟踪，也不能防止强制添加，不应宣传为安全边界；不自动执行 Git 命令修改用户索引。
- 含秘密的备份同样视为敏感数据，遵守相同权限；不默认无限保留明文历史。

## 10. 异步状态、错误与 Doctor

| 场景 | 行为 |
| --- | --- |
| 首次读取 | 原布局内显示「正在读取配置」等状态，不使用 Web 骨架屏 |
| 刷新 | 保留旧数据、选择项和滚动位置，局部标记刷新中 |
| 保存 | 防止重复提交，保留草稿；成功前不显示已保存 |
| 长任务 | 展示具体步骤；超过 3 秒补充仍在执行的状态；可安全取消的任务提供取消入口 |
| 提交临界区 | 明确暂不可取消，不提供无效的取消按钮；完成后响应退出请求 |
| 空数据 | 说明当前未配置，并提供下一步入口 |
| 失败 | 显示原因、相关路径和可执行建议；重试必须由用户触发 |

- 不用全局遮罩阻塞无关区域；任务结束、失败或取消后必须退出 loading 状态。
- 可预期的校验错误就地显示；不可恢复错误先清理终端，再输出脱敏说明。禁止空 catch、假成功和自动重试写入。
- Doctor 默认只读：检查字段完整性、引用存在性和配置一致性；不自动生成、修复、删除或替换资料。
- 未启用的平台不报缺失错误；缺少解析工具或能力时显示「未检查」，不能显示「通过」。
- 「文件存在」不等于「证书有效」；只有完成实际解析和规则校验后才报告有效期等结论，不据此声称可签名或可发布。

## 11. 验证与完成标准

不追求任意覆盖率数字，不强制个人项目搭建 CI。新增测试必须防住真实行为回归，而非断言源码写法。

| 范围 | 必须验证的行为 |
| --- | --- |
| 配置模型 | 必填与可选字段、自定义环境、未知版本拒写、损坏 JSON 不被覆盖 |

- 平台包括 Android、iOS、HarmonyOS、Windows、macOS 和小程序；平台根配置与环境签名配置分别展示对应字段。当前字段模型中的截图、宣传图各保存一个文件引用。

- 缺少工作区时，在创建渲染器、进入 raw mode／备用屏幕之前，先显示普通终端询问：`No lazyapp workspace found. Create one? (y/N): `（沿用已保存语言偏好）。仅不区分大小写的 `y` / `yes` 同意；空输入、其他回答和 EOF 都不创建文件并退出 `0`，Ctrl+C 退出 `130`。已有目标直接打开并校验，损坏配置不触发重新初始化。
- 同意后原子创建最小 `app.json`、内部 `.gitignore`（内容为 `*`）和示例目录文件，直接进入 TUI，不显示初始化向导。名称默认取项目目录名；真实 `app.json` 的平台与环境列表为空，之后在 App 分类编辑启用。
- `src/config/initialization.js` 默认生成六个平台及 development／production 的示例清单，并包含资源、服务、环境和商店模板。这些目录不代表实际启用的平台／环境。所有示例以 `.example` 结尾；图片与签名文件使用对应目标名，如 `source.png.example`、`certificate.p12.example`、`provisioning.mobileprovision.example`，内容是中英文说明，不伪造二进制文件。全部文件在私有暂存目录准备后一次发布，已有工作区拒绝覆盖。
- TUI 将示例映射为不带 `.example` 后缀的逻辑条目：只有示例时红色「缺失」，真实文件存在时绿色「存在」，不重复显示同一目标。颜色只表示存在性，不保证配置或凭据有效。浏览缺失配置不标脏；Enter 打开干净草稿，保存才创建真实配置，不读取或复制示例内容。缺失资源 Enter 询问源文件路径，确认后导入；删除真实文件保留示例并恢复红色。
- 示例不参与真实配置加载或 Doctor 校验；Doctor 仍报告真实配置缺失。文件引用若以 `.example` 结尾会被校验拒绝，不能作为真实资源／凭据。旧版 `credentials.example` 仅显示说明，不将其当作可导入的具体凭据文件。
- 已有工作区中的文件复制、覆盖、逐文件删除是单独确认的提交操作；对话框明确提示“取消后续表单编辑不会撤销已确认的文件复制”。移除外部引用只修改草稿，永不删除源文件。
- `.lazyapp.lock` 保存写锁所有者信息；遇到遗留锁拒绝写入，用户须核实所有者进程已经失效后再处理，不自动抢锁。
- 外部修改导致保存冲突时保留草稿；使用 `r` 并通过保存／放弃／取消确认重新加载，不提供静默覆盖。
- Doctor 只检查共享字段规则、引用存在性、配置一致性与权限。证书解析、有效期、签名兼容性及远程凭据认证标记为「未检查」；存在性通过不代表可签名或可发布。

### 操作提示

- 双栏左侧纵向堆叠工作区、分类、列表，右侧常驻详情与状态。`Tab` / `Shift+Tab`、`1/2/3`、`h/l` 切换三个可聚焦面板；`j/k` 移动时立即刷新详情。
- `Enter` 分层进入：分类 → 列表 → 详情编辑器 → 当前字段。详情末行的 `[ Save document ]` 与 `Ctrl+s` 都是提交入口；`Esc` 按 详情 → 列表 → 分类 回退，分类面板上请求退出。
- 切面板、滚动详情和浏览预览都不触发确认；只有改变分类、改变条目、改变搜索或新建目标时才检查脏草稿。
- 分类中 `n` 新建配置；文本编辑中 `jq/?` 等仍是文字，`Esc` 恢复该字段编辑前的原始值。
- 文件字段提供复制、外部引用、移除引用；`f` 打开托管文件列表，`d` 请求删除选中文件，`app.json` 等不可删除的项会给出说明文字而不是弹出确认。删除／覆盖／放弃默认选中取消。
- `v` 查看非敏感字段完整内容（含被面板裁剪的长值）；敏感字段在摘要、`v` 与输入中都遮蔽，不提供自动复制。`?` 显示帮助；Doctor 中 `r` 重新执行检查。
- 分类末尾的 `Settings / 设置` 是语言入口：Enter 进入列表，`j/k` 选择 `中文` 或 `English`，Enter 保存并立即应用；下次启动沿用选择。设置类别不提供文档创建、删除、文件列表、搜索和刷新操作。进入设置仍遵循脏草稿保存／放弃／取消确认。

# lazyapp 技术栈与开发规范

> 状态：保留 TUI，并提供 Bun 本地 Web 编辑器；落地契约与验证范围见第 12 节。
> 面向个人使用的本地 App 配置与附件管理工具。

## 1. 定位与边界

- 管理 App 基础信息、资源、平台配置、证书、第三方服务、环境和商店资料。
- 入口分为 `lazyapp tui [project-directory] [--port 3210]`（TUI 与 Web 同生命周期）、`lazyapp web [project-directory] [--port 3210]`（仅 Web），以及兼容入口 `lazyapp [project-directory]`（仅 TUI）。TUI 内按 `W` 可补充启动 Web；两端共用同一工作区、字段定义与业务／存储层。
- Web 默认从 `3210` 开始监听；指定端口被占用（`EADDRINUSE`）时逐一加一，直到成功或到达 `65535`。`--port 0` 由系统分配空闲端口；启动信息显示实际地址。其他启动错误不自动重试。
- 本地文件是唯一持久化来源，默认离线运行；允许仅监听 `127.0.0.1` 的本机 HTTP 服务，不引入账号、远程服务、数据库、云同步或遥测。
- 不负责构建、签名执行、发布、自动申请证书或调用第三方服务变更远端状态。
- 环境按需创建，支持自定义名称；不强制每个平台都有 development / production。
- `lazyapp.md` 保留产品构想；本文约束技术实现与交互。涉及明文风险、路径和 Git 忽略方式时，以本文的安全约束为准。
- 「必须／禁止」为实现底线；「优先／建议」允许在明确原因后调整。未涉及的功能不因本文提前实现。

## 2. 技术栈

| 类别           | 选型                            | 约束                                                                                   |
| -------------- | ------------------------------- | -------------------------------------------------------------------------------------- |
| 运行时、包管理 | Bun                            | Bun >=1.4.2；开发与 CI 固定 1.4.2；仓库不提交包管理器锁文件                            |
| 开发语言       | JavaScript，ES Modules          | 不使用 TypeScript；通过 JSDoc 描述跨模块契约                                           |
| TUI            | `@opentui/core`                 | 直接使用 OpenTUI Core，不引入 React / Vue 渲染层；Ratatui 仅可作为交互参考，不作为依赖 |
| 代码风格       | ESLint + `@antfu/eslint-config` | 使用同一配置检查和修复风格，不并行维护第二套格式规则                                   |
| 测试           | Bun + `node:test` + `expect`    | 保留现有测试适配器，使用 Bun 兼容层；覆盖配置、存储和关键交互状态                      |
| 持久化         | JSON + 原始资源文件             | 配置可人工阅读和编辑；证书、图片保持原始格式，不内嵌为 Base64                          |
| 文件与进程     | 兼容的 `node:` 内置 API         | 业务运行时代码、测试、构建与本地发行冒烟均由 Bun 执行                                 |
| 工具与日期     | 原生 JavaScript 优先            | 不因旧规范预装 xe-utils、dayjs；复杂需求出现后再统一选型                               |

- 记录实际验证的 Bun 与 OpenTUI 版本；升级后验证启动、输入、布局和终端恢复。
- 支持 macOS、Linux 与 Windows 交互终端。App 可管理的平台不等于工具已支持的运行系统；新增运行系统支持必须实测后声明。
- 已配置 `bun run dev`、`bun run web`、`bun run lint`、`bun run lint:fix`、`bun test`、`bun run build`；启动参数与实际验证范围见第 12 节。
- 使用 Bun standalone compile 内嵌运行时和 OpenTUI 原生资源；Web 页面与许可证作为相邻文件分发。

## 3. 代码组织与依赖方向

按业务模块组织，目录按需创建，不先堆空壳。

```text
src/
├── main.js             # 入口、参数、启动与退出
├── app/                # 应用壳、导航、焦点与生命周期
├── features/           # 按需添加 app、assets、platforms、services 等模块
├── shared/             # 已有复用需求的控件与纯函数
├── storage/            # 配置读写、文件导入、路径与写入保护
├── web/                # Node HTTP 适配器与本地 HTML/CSS/JS；复用 features/config/storage
└── config/             # 工具自身配置与默认值
```

- 依赖方向：`main → app 或 web → features → storage / shared / config`；底层不得反向依赖界面或业务模块。
- feature 之间不直接读取内部状态，通过应用层协调；真正共享的模型或逻辑提取到已有公共层。
- 不再同时创建 pages、components、layouts、stores 等功能重叠的目录。
- UI 负责展示与输入；业务逻辑负责校验与操作；storage 负责磁盘副作用。控件禁止直接写文件或启动进程。
- 简单逻辑就地实现；出现真实复用再抽取，不为单个调用创建通用框架、插件系统或依赖注入容器。
- 模块文件使用 kebab-case，变量和函数使用 camelCase，类使用 PascalCase，模块级固定常量使用 UPPER_SNAKE_CASE。
- JSDoc 用于导出函数、共享数据结构及不明显的约束，说明参数、结果和必要的异常语义。禁止给每个局部变量、回调重复写无信息量注释。

## 4. 状态与操作模型

- 区分三类状态：磁盘配置快照、未保存编辑草稿、焦点／选择项／滚动等临时 UI 状态。
- 一个状态只由一个明确的所有者修改；不在多个控件中复制同一份配置或 loading 状态。
- 修改表单仅更新草稿，保存成功后才更新磁盘快照并清除 dirty 标记。保存失败保留草稿。
- 离开未保存页面、切换工作区或正常退出时，提供「保存／放弃／取消」；默认不丢弃修改。
- 取消编辑不得写盘；启动询问明确回答 `y` / `yes` 前不创建工作区文件。
- 加载、成功、空、错误、取消分别建模。过期异步结果不得覆盖当前页面或新操作的状态。

## 5. 键盘、焦点与交互

键盘可完成全部核心操作，采用 Vim 风格导航，但不实现完整 Vim 模式系统。鼠标仅作增强。

| 按键              | 非文本编辑上下文中的含义                                                         |
| ----------------- | -------------------------------------------------------------------------------- |
| `j / k`、`↓ / ↑`  | 焦点面板内下移／上移；移动即刷新详情预览                                         |
| `h / l`、`← / →` | 平台树展开／收起、子项返回父平台；向右进入条目详情，详情向左返回导航 |
| `1 / 2 / 3 / 4` | 聚焦应用与资源／平台／服务环境商店／文件 Doctor 四个导航分组 |
| `0` | 聚焦共享详情编辑区，保留当前文档目标 |
| `Tab / Shift+Tab` | 在四个导航分组与详情之间循环焦点 |
| `[` / `]` | 在第三、第四组的页签之间切换，改变内容目标时确认脏草稿 |
| `Enter` | 展开／收起平台节点；打开条目；查看字段完整值；详情末行执行保存 |
| `Esc` | 关闭浮层或恢复本次字段编辑；从详情返回上次导航分组，导航上不退出 |
| `/` | 搜索焦点导航分组的文档路径；取消恢复搜索前的选择与过滤 |
| `g` / `G`         | 焦点面板首项／末项                                                               |
| `s`               | 保存当前草稿；详情面板末行同时提供可聚焦的保存行                                 |
| `?`               | 打开当前上下文的快捷键帮助                                                       |
| `q`               | 请求退出，执行未保存检查                                                         |
| `Ctrl+c`          | 有顶层弹窗时关闭该弹窗；否则请求退出                                             |

- 焦点面板使用蓝色边框，当前选中行使用与明暗主题配套的整行底色。文件／配置行缺失为红字、存在为绿字，选中后仍保留状态颜色；其他选中项使用文字色。编号标题嵌入边框，列表右下角显示当前位置／总数。
- 当前文档指示使用细箭头 `›`；平台树折叠／展开使用紧凑 `▸`／`▾`。导航不使用大实心 `▶`／`▼`，保留整行选中底色及存在／缺失颜色。
- 浏览分类、列表和详情本身不触发确认；只有改变分类、改变条目、改变搜索结果或新建目标会进入未保存确认。

- 文本输入获得焦点后，`j/k/h/l/q/?/g/G` 和 `/` 都按普通字符输入；方向键按文本编辑语义处理，不触发列表导航。
- 快捷键由统一分发层按「顶层弹窗 → 当前控件 → 当前页面 → 全局」处理，消费后停止传播。
- 任意时刻只有一个键盘焦点目标；选中态与焦点态必须能区分。
- 弹窗捕获焦点和输入，背景不可操作；关闭后恢复原焦点，原控件已删除时回退到最近可用控件。
- 删除、覆盖文件和放弃修改必须明确确认，默认焦点放在取消项；生产环境操作清晰标识目标。
- 底部展示当前可用快捷键，不宣传不可用操作。输入模式和任务状态有明确文字提示。

## 6. 布局、层级与滚动

- 顶部一行工作区信息；底部是紧凑任务／保存／错误反馈和上下文快捷键。长介绍移入帮助或操作确认，不常驻占据编辑空间。
- 双栏左侧约 33%，四组导航纵向无空隙堆叠：`[1]` 应用与资源；`[2]` 可展开的平台树，直接选择根配置／签名配置；`[3]` 服务／环境／商店页签清单；`[4]` 托管文件／Doctor 页签清单。焦点组分配剩余高度，其他组保留选中项摘要。右侧 `[0]` 共用详情／编辑区；切焦点与切编辑目标分离，只有后者确认脏草稿。
- 宽度 ≥100 且高度 ≥24 时显示四组；未达该阈值但宽度 ≥80、高度 ≥16 时显示焦点组和右侧详情；宽度 60–79、高度 ≥16 时上下堆叠焦点组与详情。更小尺寸显示空间不足，仍可退出与处理已打开确认。resize 保留草稿、目标与各组位置。
- 默认主题固定为 `gruvbox-light`／Gruvbox Light，不随终端明暗变化。缺失、未知和旧通用 `default` 偏好回退到新默认，但读取时不重写设置；已有命名主题保留。显式 `auto`／「自动（终端）」才跟随 OpenTUI 的 `themeMode` 和 `theme_mode`；晚到检测和运行中切换立即重绘（包括弹窗），不改变草稿、焦点或持久化偏好；未知模式使用不透明深色自动配色。Gruvbox Light 的普通文字与语义状态颜色在面板、弹窗及选中行上对比度至少 4.5:1。
- 主题背景同时应用于 renderer 清屏底色与文字控件；页头、状态栏、快捷键栏的尾部空白使用同一不透明底色，切换主题与 resize 后不透出终端默认黑底。选中行及弹窗的语义背景差异保留。
- `?` 打开导航／操作／须知三类帮助，默认导航类；快捷键与说明分列，按终端列宽换行。左右方向键或 `[`/`]` 切分类，上下与 PgUp/PgDn 滚动并显示位置；每类保留本次打开期间的滚动位置。Esc／Enter 关闭恢复原焦点。存储、凭据、文件导入和诊断安全说明集中在须知类；缩放不关闭帮助，过小窗口仍可打开、切换与关闭帮助。
- 不沿用 CSS z-index。只保留「基础内容 → 弹窗 → 弹窗内选项」的覆盖顺序；普通通知放在状态栏，禁止夺取焦点或盖住确认操作。OpenTUI 中该顺序由渲染节点创建顺序决定，弹窗节点必须在所有面板节点之后创建，否则面板会覆盖对话框。
- 每个面板明确滚动边界，只有焦点所在区域处理滚动；列表与详情可各自滚动，但同一输入不能同时滚动两处。
- resize 后重新计算可用空间，保留草稿、当前项与可恢复的滚动上下文，禁止越界绘制。
- 导航时选中项始终可见；返回列表、刷新数据或请求失败时，优先按稳定 ID 恢复当前项与滚动位置，目标消失时选择最近有效项。
- 大列表仅构建可视范围附近的行；禁止每次按键重建全部数据或读取全部资源内容。
- 路径、中文、全角字符按终端显示宽度裁剪，不使用字符串长度代替列宽；长文本提供详情查看，不撑破布局。
- 不依赖 Nerd Font、Emoji 或复杂 Unicode 图标；状态使用文字，颜色仅作辅助，边框提供 ASCII 降级。
- 颜色统一使用语义 token：text、muted、accent、success、warning、error、border、focus；不得在业务模块散落 ANSI 转义序列。

### Web 滚动

- 固定应用壳承载顶部工作区和底部状态栏，`main#content[data-scroll-root]` 是唯一页面主滚动区；`html`／`body` 不滚动，页面禁止横向滚动。主区、侧栏和虚拟列表可键盘聚焦，保留可见焦点边框。
- `src/web/public/scroll.js` 统一管理视图滚动策略：进入总览或打开不同配置从顶部开始；返回文件／Doctor 恢复主区及可见局部清单位置；同一配置保存、刷新及失败不重置上下文。状态只在内存保存，不写 `localStorage`；过期异步恢复不得覆盖新导航。
- 侧栏是有明确高度的独立 `scroll-section`。配置清单、文件清单、诊断结果共用 `virtual-list.js`，超过 100 项启用固定行高窗口，每侧预渲染 4 行；长路径有边界，不靠内容撑大行高。按稳定键保留焦点，目标消失时落到最近有效行；支持方向键、PageUp／PageDown、Home／End，文本控件不接管这些按键。
- 移动导航与确认框使用原生 `dialog`，内容独立滚动。打开前锁定背景主区和侧栏，嵌套弹窗全部关闭后才恢复原样式和位置；抽屉内清单的位置由管理器单独记忆。移动抽屉内侧栏不再叠加一个滚动容器；切回桌面关闭抽屉并归还侧栏。
- 滚动监听和订阅由管理器集中持有，以 `requestAnimationFrame` 合并更新；虚拟列表只观察容器尺寸，不逐行观察。实际离开页面时清理监听、RAF、尺寸观察与缓存；进入浏览器 BFCache 时保留可恢复的页面实例。
- 锚点走 `scrollToAnchor` 并计算最近明确滚动边界与 `scroll-margin-top`；禁止业务代码直接调用 `window.scrollTo`／`scrollIntoView`。只对显式返顶／锚点按需平滑滚动，`prefers-reduced-motion` 下即时定位，不全局开启 smooth。
- 主区滚动超过 400px 显示 `z-index: 200` 的局部返顶按钮。表单操作栏绑定主滚动区吸底，并以 `scroll-padding-bottom` 预留操作栏及窄屏换行空间，防止 Tab 聚焦的字段被遮挡；抽屉标题绑定抽屉吸顶。局部滚动使用原生触摸滚动和 overscroll 边界，不拦截正常内容滚动。
- 操作反馈在固定高度底部状态栏内，长反馈有明确的局部滚动边界；出现成功／错误消息不向下推移表单。图片预留 4:3 预览框；刷新保留已有数据，不先清空列表或用不同高度占位替换。
- 当前没有表格组件，不额外引入 Table 框架；后续表格横向滚动必须局限于表格内部，固定行列使用所选组件能力。大清单用窗口化及 RAF 控制计算，不引入遥测或为未出现的性能问题添加监控框架。


## 7. 终端生命周期

- 启动前检查交互所需的 stdin / stdout TTY；不满足时向 stderr 输出说明并非零退出，不进入 raw mode。
- 渲染器统一持有终端；进入 TUI 后禁止 `console.log` 或子进程直接往终端写入，避免破坏画面。
- raw mode、备用屏幕、光标与事件监听由入口统一管理；正常退出、初始化失败、可捕获异常和 SIGINT / SIGTERM 均执行幂等清理。
- 正常用户退出或拒绝初始化返回 0；启动、读写或未恢复的运行错误返回非零；信号退出使用对应约定退出码。
- SIGTERM 尽力恢复终端，但不弹出等待输入的对话框，也不自动保存草稿；SIGKILL 等不可捕获终止无法保证清理或草稿保留。
- 文件操作及外部命令异步执行，不阻塞输入循环。外部命令使用程序名与参数数组，禁止将用户输入拼接进 shell 命令。
- 默认捕获子进程输出；需要交互式外部程序时先暂停 TUI、恢复终端，结束后重建画面与焦点。
- 若支持后台挂起／恢复，必须同步处理终端状态；未经验证不绑定挂起快捷键。

## 8. 数据与文件约定

### 工作区与配置

- 工具源码目录与用户项目中的 `<project>/.lazyapp/` 数据目录是两种概念，不混用。
- 默认只查找 `<cwd>/.lazyapp/app.json`；不自动向父目录扫描并写入其他项目。不存在时询问初始化，取消不留文件。
- 目标目录已存在但不是有效工作区时显示冲突，不静默接管或覆盖。界面持续显示实际工作区路径。
- `app.json` 保存 App 元数据及 `schemaVersion`；平台配置、服务、环境和资源按 `lazyapp.md` 的分类按需落盘。
- JSON 使用 UTF-8、2 空格缩进和末尾换行。字段默认值、必填条件和敏感属性集中定义，UI 与 Doctor 复用同一套规则。
- 环境名称必须是安全的单个目录名，不接受空值、`.`、`..`、分隔符和路径穿越；大小写冲突按目标文件系统处理。
- 工具设置与业务环境分开；工具配置集中读取，不照搬 `VITE_*` 或自动加载业务 `.env` 文件的机制。
- 界面语言是用户级偏好，保存于 `$XDG_CONFIG_HOME/lazyapp/settings.json`（XDG 路径须为绝对路径）；未配置时使用 `~/.config/lazyapp/settings.json`。格式为 `{"schemaVersion":1,"language":"en"}` 或 `"zh"`。文件不存在时默认 English 且读取不创建文件；仅明确选择语言才保存。设置不属于 App 工作区。
- 语言偏好使用私有目录／文件权限、同目录临时替换和独占写锁。损坏 JSON、不支持的版本／语言、设置路径符号链接均拒绝覆盖；保存失败保持当前语言与业务草稿。保留未知设置字段。
- 不支持的 schemaVersion 明确报错并禁止写入；迁移必须有具体版本转换、备份和确认，不静默丢字段。
- 读取失败或 JSON 损坏不得当作空配置覆盖；保存已支持版本时保留未编辑字段。

### 文件导入与路径

- 默认复制文件到工作区；用户也可明确选择引用外部文件。复制前验证源文件可读，覆盖目标前确认。
- 工作区内的引用统一相对工作区根目录保存，禁止混用相对各级 config.json 的路径。外部引用保存明确的绝对路径，并提示不可随工作区迁移。
- 例如 iOS App Store 证书内部引用为 `platforms/ios/app-store/certificate.p12`，解析时以工作区根目录为基准。
- 管理目录内的写入、删除必须校验规范化路径及已有父目录的真实路径，禁止通过 `..` 或符号链接越出工作区。
- 外部引用只读：解除引用不删除源文件；复制导入同样不修改源文件。

### 写入可靠性

- 单文件保存使用同目录临时文件写入后替换，成功前不得截断原文件；失败清理临时文件并保留草稿。
- 同一工作区串行写入；最初实现采用工作区独占写锁，第二个实例拒绝进入可写状态。锁有所有者信息，异常遗留锁只在确认失效后处理。
- 写入前比较读取时的内容与当前磁盘版本；检测到外部修改时提示重新加载或显式覆盖，不静默覆盖。
- 外部编辑器不遵守锁，写前检查不保证消除并发竞态；不承诺与其他程序同时写入安全。
- 初始化等多文件操作先在暂存区准备，校验通过后提交；涉及已有文件的多文件变更必须定义恢复方案，不把多次 rename 当成整体原子事务。
- 删除采用逐项明确目标的操作，禁止根据未经校验的配置路径递归删除目录。

## 9. 敏感信息与本地安全

- 允许按个人使用方式在本地保存明文密码、Token 和私钥，但必须明确：本地目录不是加密保险箱；备份、同步软件、恶意进程和误提交仍可能泄漏数据。
- 不默认引入主密码、Keychain 或加密服务，也不把「未上传 Git」当成安全保证。
- 密码、Token 等输入默认遮蔽；已有敏感值默认隐藏，仅在明确操作后显示，离开详情即恢复隐藏。
- 日志、错误、Doctor 和普通摘要禁止输出敏感值、证书正文或完整配置；敏感字段不参与普通全文搜索。
- 复制敏感信息只能由用户显式触发，并提示剪贴板可能被历史工具记录；不自动复制或宣称已安全清除历史。
- POSIX 下新建数据目录使用 `0700`、配置／证书／临时文件使用 `0600`；现有权限过宽时提示，不修改外部引用文件权限。
- 初始化在**数据目录内部**创建 `lazyapp/.gitignore`，内容为 `*`，忽略该目录内所有未跟踪文件；不在这里写 `.lazyapp/`，它匹配的是下一级同名目录。
- `.gitignore` 不会取消已有 Git 跟踪，也不能防止强制添加，不应宣传为安全边界；不自动执行 Git 命令修改用户索引。
- 含秘密的备份同样视为敏感数据，遵守相同权限；不默认无限保留明文历史。

## 10. 异步状态、错误与 Doctor

| 场景       | 行为                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 首次读取   | 原布局内显示「正在读取配置」等状态，不使用 Web 骨架屏                   |
| 刷新       | 保留旧数据、选择项和滚动位置，局部标记刷新中                            |
| 保存       | 防止重复提交，保留草稿；成功前不显示已保存                              |
| 长任务     | 展示具体步骤；超过 3 秒补充仍在执行的状态；可安全取消的任务提供取消入口 |
| 提交临界区 | 明确暂不可取消，不提供无效的取消按钮；完成后响应退出请求                |
| 空数据     | 说明当前未配置，并提供下一步入口                                        |
| 失败       | 显示原因、相关路径和可执行建议；重试必须由用户触发                      |

- 不用全局遮罩阻塞无关区域；任务结束、失败或取消后必须退出 loading 状态。
- 可预期的校验错误就地显示；不可恢复错误先清理终端，再输出脱敏说明。禁止空 catch、假成功和自动重试写入。
- Doctor 默认只读：检查字段完整性、引用存在性和配置一致性；不自动生成、修复、删除或替换资料。
- 未启用的平台不报缺失错误；缺少解析工具或能力时显示「未检查」，不能显示「通过」。
- 「文件存在」不等于「证书有效」；只有完成实际解析和规则校验后才报告有效期等结论，不据此声称可签名或可发布。

## 11. 验证与完成标准

不追求任意覆盖率数字，不强制个人项目搭建 CI。新增测试必须防住真实行为回归，而非断言源码写法。

| 范围       | 必须验证的行为                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| 配置模型   | 必填与可选字段、自定义环境、未知版本拒写、损坏 JSON 不被覆盖                                                    |
| 存储       | 保存后可重新读取；写入失败保留原文件；路径越界拒绝；外部文件不被删除；写锁冲突与外部修改提示                    |
| 编辑状态   | 保存清除 dirty；失败保留草稿；取消不写盘；离开提示可取消                                                        |
| 输入与焦点 | 输入 `jq/?` 不触发导航或退出；弹窗拦截背景按键；关闭后焦点恢复；面板切换键只在工作区生效                        |
| 安全       | 常规日志／摘要不含秘密；文件权限与忽略规则符合约定                                                              |
| 实际终端   | 启动、向导取消、编辑保存、返回、退出、resize、长路径与中文、异常后的终端恢复；面板焦点边框与三面板/单栏布局切换 |

- 纯逻辑和磁盘行为用 `node:test`；测试使用临时目录与虚构凭据，不读取或修改真实 App 资料。
- TUI 改动必须在实际终端执行受影响流程；状态单测不能代替焦点、显示宽度和终端恢复验证。
- 对双栏、单栏、空间不足三种布局分别检查；对正常退出和可捕获异常分别检查光标与输入恢复。
- 最小端到端验收：在临时项目初始化 → 编辑并保存 → 退出重开数据一致 → 取消修改不落盘 → Doctor 正确区分缺失与未检查。
- 功能完成时运行相关测试和 lint，记录实际终端验证结果；只修改本文时仅做文档一致性检查，不声称运行不存在的工程测试。
- 行为或数据契约变化时同步相关规范与测试；不为尚未实现的功能添加空测试、空模块或占位命令。

## 12. 第一阶段实现与运行记录

### 运行

- 使用 Bun `1.4.2`、`@opentui/core` `0.5.11`；直接依赖版本固定在 `package.json`，仓库按约定不提交锁文件。实际本地验证范围与历史记录分开记录。
- 先确保 Bun >=1.4.2 在 `PATH` 中，再运行 `bun install`；`bunfig.toml` 禁止写入锁文件。
- `lazyapp tui /absolute/project` 同时启动 TUI 与 Web；`--port` 默认 3210，`0` 自动分配。`lazyapp /absolute/project` 与 `bun run dev /absolute/project` 保持仅 TUI；TUI 内按 `W` 可启动默认端口 Web。省略项目参数只使用当前目录。
- `bun src/main.js --help` 无需 TTY；源码 TUI 使用 `bun src/main.js tui [project-directory]`，必须有交互式 stdin/stdout。Bun 独立发行包内置运行时与 OpenTUI 原生资源，不要求宿主安装 Bun 或 Node.js，也不再需要 `--experimental-ffi`。

### mise 安装与 GitHub Release

- 发布仓库为 `wei-py/lazyapp`，发行包覆盖五个目标：macOS（arm64、x86_64）、Linux（x86_64、arm64）与 Windows（x86_64）。
- 在各目标平台使用固定 Bun 1.4.2 执行 `bun install`、`bun run build`。构建通过 `Bun.build({ compile: ... })` 内嵌运行时与 OpenTUI 资源；Linux 显式选择 glibc，Bun 目标使用 `darwin`／`linux`／`windows` 平台名称。macOS 在编译及可执行权限设置完成后，以固定 `lazyapp` 标识和无时间戳的 ad-hoc 签名重新封装最终二进制，再执行 `codesign --verify --strict`；签名或校验失败均终止构建，之后才归档并生成校验和。重新签名保留 Bun 现有的 entitlements（包括存在时的 JIT 权限）、签名选项与 hardened runtime 版本，不继承原 Developer ID 身份要求，也不需要证书或发布密钥；不再维护 Node SEA 打包、资源解压或 Node entitlements。输出 `dist/lazyapp-<slug>.tar.gz`（Windows 为 `dist/lazyapp-windows-x64.zip`）和 `dist/SHA256SUMS`；压缩包包含 `bin/lazyapp`（Windows 为 `bin/lazyapp.exe`）、`bin/web/` 本地页面资源与第三方依赖许可。`dist/` 不提交 Git。
- `bun run smoke:source` 和 `bun run smoke:release` 仅供本地验证，覆盖真实 PTY 初始化、重开、缩放、退出及 Web 静态资源、鉴权只读 API 与服务关闭。macOS 发行包额外验证签名，并禁止非交互检查读取源码仓库。CI/CD 不得执行这些命令，也不得用直接启动二进制等方式变相执行冒烟。
- 第三方许可收集从依赖所属包的模块搜索路径定位已安装目录，不解析或加载包入口；仅导出 ESM／Bun 入口的传递依赖同样保留许可证，不要求 CommonJS 导出。按实际安装目录遍历，许可写入 `licenses/<包名>/<版本>/`，避免同名不同版本被跳过或相互覆盖。
- OpenTUI 原生包是 `@opentui/core` 的可选依赖，不是项目直接依赖。收集其许可时以 `@opentui/core` 的实际安装目录为解析起点；Linux 构建选择的 libc 与原生包许可保持一致。
- 构建检查 `package.json` 的 Bun 最低版本；OpenTUI 资源由 Bun 编译器内嵌与管理，不再维护应用专属的临时原生资源目录。
- `--update` 同时安装可执行文件与相邻 `web/`，缺少必需页面文件时拒绝更新。在安装目录所在文件系统暂存后替换，操作失败时回滚旧二进制与页面；回滚失败会报告并保留恢复文件。Windows 保留运行中的旧二进制为 `.old`；这不是断电／进程强杀下的跨文件原子事务。
- 运行仍以当前目录或显式项目路径发现工作区，不以可执行文件安装目录发现工作区。
- `.github/workflows/release.yml` 在推送 `v*` tag 时于全部目标平台分别安装依赖并构建；全部构建成功后创建 GitHub Release，上传各平台压缩包与合并的 SHA-256 校验文件。工作流不运行 lint、行为测试或 `smoke:release`，这些命令保留供本地验证。tag 必须严格等于 `v` 加 `package.json` 的版本，例如 `v0.2.1` 对应 `0.2.1`，不匹配会拒绝构建。
- 首次发布：先提交并推送这些改动，再执行 `git tag v0.1.0` 和 `git push origin v0.1.0`。后续发布先更新 `package.json` 版本，再推送对应新 tag；不要移动已发布 tag。GitHub Actions 的手动运行只构建并保留附件，不创建 Release。
- Release 成功发布后执行：

  ```sh
  mise use -g github:wei-py/lazyapp@latest
  mise exec github:wei-py/lazyapp@latest -- lazyapp --help
  ```

  已激活 mise 的终端可直接执行 `lazyapp /absolute/project`。固定版本可改用 `github:wei-py/lazyapp@0.1.0`。`github:` 后端安装上传的 Release 附件，不会克隆源码执行构建；仅推送源码或创建无附件的 tag 不足以安装。

- 当前二进制未做 Apple Developer ID 签名或公证，不宣称已通过 Gatekeeper 分发验证。

### 已落地的数据契约

所有配置都是带 `schemaVersion: 1` 的 JSON 对象；未编辑的未知字段保留。字段定义与校验集中在 `src/config/model.js`，UI 和 Doctor 共用。

| 路径                                             | 内容                                                                    |
| ------------------------------------------------ | ----------------------------------------------------------------------- |
| `app.json`                                       | `name`、`description`、`version`、`platforms` 数组、`environments` 数组 |
| `assets/config.json`                             | 图标、启动图、截图、宣传图，以及 `waiver`（免责函）、`businessLicense`（营业执照）、`softwareCopyright`（软著）、`copyrightSupplement`（软著补充材料）的文件引用 |
| `platforms/<platform>/config.json`               | 平台身份与通用配置                                                      |
| `platforms/<platform>/<environment>/config.json` | 该平台环境的签名资料与凭据引用                                          |
| `services/<name>.json`                           | 服务身份、API 凭据、外部端点及凭据文件                                  |
| `environments/<name>.json`                       | 环境名称、API/Web/CDN 等地址、敏感变量                                  |
| `store/<name>.json`                              | 商店名称、文案、链接与图片引用                                          |

- 平台包括 Android、iOS、HarmonyOS、Windows、macOS 和小程序；平台根配置与环境签名配置分别展示对应字段。当前字段模型中的截图、宣传图各保存一个文件引用。
- HarmonyOS 平台根配置提供可选 `material` 文件字段，用于引用已有 `material/` 目录压缩得到的 ZIP，推荐路径为 `platforms/harmony/material.zip`，压缩包保留 `material/` 顶层目录。该字段不属于单环境签名配置；未填写不影响完整性检查，填写后沿用附件路径校验与存在性检查。新工作区仅生成 `platforms/harmony/material.zip.example` 说明，不生成虚假压缩包，不解压或验证包内凭据。
- 名称使用安全单段目录名，拒绝前导点、路径分隔符、控制字符与不可移植文件名。内部文件引用另拒绝点前缀组件、冒号和反斜杠；明确外部引用必须为绝对路径且只读。
- 缺少工作区时，在创建渲染器、进入 raw mode／备用屏幕之前，先显示普通终端询问：`No lazyapp workspace found. Create one? (y/N): `（沿用已保存语言偏好）。仅不区分大小写的 `y` / `yes` 同意；空输入、其他回答和 EOF 都不创建文件并退出 `0`，Ctrl+C 退出 `130`。已有目标直接打开并校验，损坏配置不触发重新初始化。
- 同意后原子创建最小 `app.json`、内部 `.gitignore`（内容为 `*`）和示例目录文件，直接进入 TUI，不显示初始化向导。名称默认取项目目录名；真实 `app.json` 的平台与环境列表为空，之后在 App 分类编辑启用。
- `src/config/initialization.js` 默认生成六个平台、development／production 业务环境，以及资源、服务和商店模板。iOS 签名用途独立于业务环境，固定提供 `platforms/ios/development/`、`platforms/ios/ad-hoc/`、`platforms/ios/app-store/`，不再生成含义模糊的 iOS `production/` 模板；其他平台仍按业务环境提供签名模板。这些目录不代表实际启用的平台／环境。所有示例以 `.example` 结尾；图片与签名文件使用对应目标名，如 `source.png.example`、`certificate.p12.example`、`provisioning.mobileprovision.example`，内容是中英文说明，不伪造二进制文件。全部文件在私有暂存目录准备后一次发布，已有工作区拒绝覆盖，也不自动迁移已有签名目录。
- `lazyapp init [project-directory]` 与 TUI 首次创建共用上述模板。每种 iOS 签名目录包含 `config.json.example`、`certificate.p12.example`、`provisioning.mobileprovision.example`；配置和凭据说明都标明用途、证书类型、UDID 与调试限制。Development 使用 Apple Development 证书和开发描述文件，需登记 UDID、允许调试；Ad Hoc 使用 Apple Distribution 证书和 Ad Hoc 描述文件，需登记 UDID、不允许附加调试器；App Store 使用 Apple Distribution 证书和 App Store 描述文件，用于 TestFlight／正式上架，无需登记 UDID、不允许附加调试器。`ad-hoc`／`app-store` 不加入业务环境列表。
- TUI 将示例映射为不带 `.example` 后缀的逻辑条目：只有示例时红色「缺失」，真实文件存在时绿色「存在」，不重复显示同一目标。颜色只表示存在性，不保证配置或凭据有效。浏览缺失配置不标脏；Enter 打开干净草稿，保存才创建真实配置，不读取或复制示例内容。缺失资源 Enter 询问源文件路径，确认后导入；删除真实文件保留示例并恢复红色。
- 示例不参与真实配置加载或 Doctor 校验；Doctor 仍报告真实配置缺失。文件引用若以 `.example` 结尾会被校验拒绝，不能作为真实资源／凭据。旧版 `credentials.example` 仅显示说明，不将其当作可导入的具体凭据文件。
- 已有工作区中的文件复制、覆盖、逐文件删除是单独确认的提交操作；对话框明确提示“取消后续表单编辑不会撤销已确认的文件复制”。移除外部引用只修改草稿，永不删除源文件。
- `.lazyapp.lock` 保存写锁所有者信息；TUI、CLI 和 Web 使用操作级写锁，允许同时打开，提交时独占加锁、检查版本，结束立即释放。底层默认独占会话接口仍供初始化和显式独占调用使用。遇到遗留锁拒绝写入，用户须核实所有者进程已经失效后再处理，不自动抢锁或重试。
- 外部修改导致保存冲突时保留草稿；使用 `r` 并通过保存／放弃／取消确认重新加载，不提供静默覆盖。
- Doctor 只检查共享字段规则、引用存在性、配置一致性与权限。证书解析、有效期、签名兼容性及远程凭据认证标记为「未检查」；存在性通过不代表可签名或可发布。

### 操作提示

- `1–4` 聚焦四组导航，`0` 聚焦详情；`Tab` / `Shift+Tab` 循环焦点。每组记住选择和过滤；第三组、第四组用 `[` / `]` 切页签。焦点变化不替换右侧活动目标，选择具体条目才切换。
- 平台节点 Enter 或右方向展开，左方向收起／返回父平台；子项直接进入平台根配置或签名配置，不增加中间分类面板。展开／收起树不丢弃现有草稿。
- 配置条目 Enter 进入共享编辑区，`e` 编辑字段或打开文件操作；普通字段 Enter 查看完整值，秘密值不展开。最后一行 Enter 与 `s` 都执行保存；`y` 显式复制字段值，状态仅显示标签。
- 切条目、切内容页签、提交搜索或新建目标时确认脏草稿，取消恢复原目标；保存失败保留输入和版本。文本输入中的数字、括号和导航字母保持普通文字。
- `a` 在当前配置分组中新建；`f` 打开托管文件组；`D` 删除当前具体文件／配置（确认，默认取消）。平台父节点、Doctor 结果不作为文件删除，`app.json` 不可删除。
- `r` 重载当前编辑器或刷新清单；Doctor 页签中重新执行只读检查。`Esc` 从详情回到上次导航组；`q` / `Ctrl+c` 请求退出，有任务时先确认。
- `:` 打开语言／主题设置；`L` 切换语言。偏好保存成功后生效，设置失败不伪装成功。
- 语言切换覆盖 TUI 面板、字段标签、帮助、确认框、错误与诊断文案；用户输入、文件路径、配置键、平台标识和按键本身不翻译。启动初始化询问使用已保存语言；命令行 `--help` 与参数／TTY 诊断仍为英文。

### 本地 Web 编辑器

- `lazyapp tui /absolute/project [--port 3210]` 由 TUI 启动并持有 Web 服务；TUI 退出或可捕获失败时一并关闭。已有 TUI 可按 `W` 启动一次，重复按键只显示当前地址。`lazyapp web /absolute/project [--port 3210]` 仅运行 Web。默认端口 3210，`--port 0` 分配可用端口；不自动启动浏览器、不扫描父目录。仅 Web 不自动初始化；缺失工作区先用 CLI `init` 或 TUI 明确创建。
- `src/web/public/index.html` 使用本地 `style.css` 和原生 ES 模块 `app.js`／`scroll.js`／`virtual-list.js`：左侧四组紧凑导航与平台树、右侧共享编辑器。基本信息／文件引用／凭据分区，保存／重载／放弃栏吸底；窄屏使用独立滚动导航抽屉，选择后回到编辑区。操作结果移至固定底部状态栏，不推移页面内容。删除冗余介绍文案，导入独立提交、覆盖／删除和外部引用风险仍明确提示。不依赖 CDN、远程字体或框架。`Ctrl/⌘+S` 通过表单校验提交，弹窗打开时不触发后台保存。
- Web 默认打开「总览」，入口位于侧栏顶部，并随窄屏导航移入抽屉。复用 `/api/state` 的磁盘快照，仅显示 App 名称／描述／版本、启用平台和环境、已存在配置与内部文件数量，以及分类存在／缺失清单；不展示服务或签名凭据，不统计未保存草稿，不自动调用 Doctor。文件统计区分工作区文件和外部引用，存在性不代表签名或发布就绪。
- 总览可以直达现有或缺失配置的编辑草稿、文件清单与 Doctor；空分类的新建入口预选对应类型，保存前不创建配置。离开脏编辑器仍提供默认取消的保存／放弃／取消确认，保存失败或取消都保留原草稿。移动端选择当前总览或当前配置也会关闭导航抽屉，不丢弃草稿；各视图复用现有主滚动区，不新增嵌套页面滚动。
- Web 共用字段／作用域配置编辑、缺失配置创建、未知字段保留、保存／放弃／取消与失败保留草稿。敏感字段默认遮蔽；页面显式显示后只供当前使用者查看，服务不记录提交内容。
- 文件保存原始字节，不写 Base64 到 JSON。支持上传、替换、下载、逐文件删除；PNG／JPEG／GIF／WebP 可预览，HTML／SVG 等主动内容只下载。Web 将位于当前 `.lazyapp` 根目录下的绝对引用映射为工作区相对路径用于存在性显示、预览与下载，不改写配置中的原始引用、不生成重复文件条目；读取仍拒绝越界路径、隐藏路径与符号链接。上传／删除仍只接受相对路径；真正的外部绝对引用不能由 HTTP 服务读取、修改或删除。
- 文件引用表单在路径及状态下直接展示 160×120 预览框，文件清单展示 64px 缩略图；实际 PNG／JPEG／GIF／WebP 按原比例完整显示，点击打开原图弹窗。编辑路径或移除引用立即清除旧图；缺失、空引用和外部引用禁用预览／下载，外部引用明确说明网页不读取。其他文件及无法预览的图片按扩展名显示文件图标，未知类型显示通用文件图标。图标采用 [UnoCSS Icons preset](https://unocss.dev/presets/icons) 与 VSCode Icons，本地生成并提交 `src/web/public/icons.css`，新增图标后运行 `bun run icons`；运行时不请求 CDN。
- 附件导入是独立提交；之后放弃配置草稿不会撤回已导入文件。替换／删除前确认，默认取消；使用文件内容版本防止静默覆盖其他界面的修改。配置引用不会因删除文件自动清空，Doctor 报告缺失。
- 仅监听 IPv4 本机地址；API 使用每次启动生成的内存令牌，检查 Host，写请求检查精确 Origin；不启用 CORS。响应禁用缓存，页面 CSP 禁止外部资源，下载禁 MIME 嗅探。令牌不放 URL／本地持久化；本机恶意进程和有权限的浏览器扩展不在隔离边界内。
- Web 文件上传上限 32 MiB，JSON 请求上限 1 MiB；现有配置只能通过共享校验保存，不能通过附件接口覆盖。Doctor 保持只读，文件存在与凭据有效性分开报告。
